# 工作台详情与组织数据口径

## 使用方式

工作台顶部的红黑榜、收到的 Thank You、已排工时和早例会事项均可点击查看只读详情。弹窗支持内部滚动、关闭按钮和 Escape，长文本自动换行。

- 积分按积分日期、工时按排班日期，沿用顶部开始和结束日期。
- Thank You 沿用现有统计的“所属周起始日”筛选，不是按发送时间筛选；弹窗同时显示所属周和发送时间。
- 早例会统计当天事项，包含保留至下一个工作日的已完成回顾项，不受顶部月度范围改变。
- 普通用户查看本人；管理员切换到管理视图后可在“查看成员”中选择授权范围内的成员。选择下级成员是单人查阅，不会将整个下级团队合并进当前团队统计。
- 黑榜积分和明细分别遵循管理员设置。隐藏积分不伪装成 0 分，隐藏明细会显示说明。加载失败或无模块访问权限时，统计显示“暂不可用”，详情入口禁用。

## 组织范围核查（2026-09-15）

结论：上层组织不是所有模块都自动汇总下层。现有系统有以下不同口径，本次保留原有业务边界，不做全局扩权。

| 模块 | 当前读取口径 | 上层是否直接汇总下层 |
| --- | --- | --- |
| 工作台四项统计 | 本人，或管理员明确选择的单人成员 | 否 |
| 红黑榜名单/积分 | 当前组织直属、已纳入红黑榜的成员 | 否 |
| 排班/工时 | 当前组织直属成员 | 否 |
| 早例会/签到名单 | 当前组织直属参与成员 | 否 |
| Thank You 排名 | 当前组织直属接收者；发送方限当前及祖先组织（管理员指定成员查阅例外） | 否 |
| Thank You 明细/候选人 | 接收者可在可访问下级树内；发送方按当前及祖先组织过滤；不向无关兄弟团队公开 | 部分跨层可见，但不是统一累计排名 |
| 团队成员 | 组织可见范围与参与名单交集 | 可见范围为子树时会包含下级 |
| 会议列表 | 组织可见范围，加祖先组织会议；签到仍按直属成员 | 可包含下级，且可继承上级会议 |
| 讨论区 | 组织可见范围内主题；仅公告额外从祖先继承 | 取决于可见范围，普通主题不会向下继承 |
| 流程模板 | 组织可见范围加祖先模板 | 可包含下级及上级模板 |
| 流程事项 | 组织可见范围；普通用户只看本人，管理员可切换范围 | 取决于组织和人员筛选 |
| 团队时刻/机台/会议议题库 | 当前组织独立内容和配置 | 否，不从上下级继承 |
| 常用链接/红黑榜规则库 | 共享库，由模块权限控制；没有逐组织隔离 | 不是汇总，而是共享数据 |

“可见范围”还要与登录用户可访问的组织求交集；切换页面中的组织路径不会绕过服务端权限。

### 后续决策点

1. 若需要部门整体 KPI，建议新增明确标注“本级 / 含下级”的汇总视图，而不是改变排班、签到和个人工作台的现有默认行为。
2. 常用链接和规则库目前是共享库。如果需要独立维护，需补组织归属、历史数据迁移和共享例外，不应只做前端隐藏。
3. 红黑榜、排班和感谢等人员数据按用户当前组织关联。人员调组后的历史归属没有统一的事件时组织快照；严格历史组织报表需要另行设计快照与迁移策略。

## 开发约定

- `static/dashboard-details.js` 负责详情渲染和原生 dialog，`dashboard-details.css` 仅作用于工作台入口和该弹窗。
- `GET /api/dashboards/red-black`、`/thank-you`、`/shifts` 可带 `include_details=1`，在原响应上增加 `details`；不带参数时不执行明细查询。
- 明细与统计在同一处理函数复用日期、组织及业务参与条件。普通用户明细始终限制本人，管理员 `user_id` 必须通过工作台组织范围校验。访客不返回个人明细。
- 红黑榜额外返回 `show_black_details`；黑榜积分被隐藏时，其可见明细的 `points` 为 `null`。
- 前端只展示最新用户、组织、成员、日期和视图上下文对应的响应；切换或退出登录后不复用过期明细。
- 回归：`python scripts/organization_scope_smoke_test.py`、`node scripts/dashboard_details_test.mjs`。测试使用临时数据库，涵盖父子组织、兄弟越权、日期、明细和统计一致性及黑榜独立开关。
