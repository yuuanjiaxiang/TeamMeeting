# 会议工作区

## 使用

纪要按用户提供的黑白表格样例：居中“会议纪要”标题，会议主题、时间、地点、主持人、记录人、参会人员信息表，随后为“会议内容、会议讨论事项、会议待办事项”。每条内容独立成行，章节使用浅灰底。会议内容引用背景和结论，讨论事项引用风险/待确认，待办引用下一步、责任人和截止日期。未记录的地点、记录人显示“未填写”，不从示例编造；现有召集人用作主持人默认值。HTML、Markdown 和富文本复制使用同一生成器。

- 左侧按整月或本周查找会议，支持标题关键字和状态筛选；历史会议不会因日期已过而消失。
- 月历默认折叠；同一天有多场会议时可直接选择会议。
- 右侧分为议程、会议纪要、签到视图。议程展示负责人、预计开始时间及记录状态，可筛选未记录和未分配议题。
- 新增自定义议题、议题库管理采用弹窗；已完成或归档会议继续遵守原有只读权限。
- 在会议纪要视图预览、复制或下载 HTML / Markdown。是否附带 Thank You 内容由勾选项决定。
- 生成邮件会复制纪要并尝试打开本机邮件客户端，不代表服务器已经发送邮件。

## 二次开发与验证

- `static/meeting-workspace.js`：列表、视图状态、筛选、弹窗和导出交互。
- `static/meeting-workspace.css`：仅针对会议工作区的响应式样式。
- `static/meeting-minutes.js`：纯函数，统一生成预览、富文本复制及下载内容；用户内容必须 HTML 转义。
- `static/app.js`：注入原有 API、组织作用域和权限函数，不在新模块重复实现认证。
- 执行 `node scripts/meeting_minutes_test.mjs`，并检查桌面、窄屏的议程与纪要视图。
- 邮件采用内联样式和表格排版；不同邮件客户端粘贴的实际结果仍需在部署环境验证。
- 本次会议界面调整无需数据库迁移，不修改 SSO 协议或连接池适配。
